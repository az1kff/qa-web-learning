Заявки на услуги · лаборатория

1. Скопируй exercise.mjs и exercise.test.mjs в отдельную папку на D. Работай в копии.
2. Открой терминал из этой папки и запусти node --test exercise.test.mjs.
3. Изучи первое падение. Предскажи результат на этом и соседнем значениях.
4. Исправь свою копию exercise.mjs. Снова запусти тесты. Добавь один свой сценарий.
5. Приложи diff или коммит. Укажи, почему проверка ловит нужное поведение.
Начальная заготовка специально проваливает тесты.

SQL и CI
Открой локальную копию sql-practice.mjs, укажи свой SELECT в переменной query и запусти node sql-practice.mjs (Node.js 24.10 или новее).
Сначала выведи заявки со статусом open. Затем сгруппируй по услугам и покажи услугу без заявок.
Файл ci-node-tests.yml можно положить в .github/workflows/ своего учебного репозитория, если exercise.test.mjs и exercise.mjs находятся в корне.
Проверь шаг с тестами на pull request. Для сравнения пригодятся отчёт на дефектной версии и отчёт после исправления.

API стенда
GET     http://127.0.0.1:4176/api/requests      список
POST    http://127.0.0.1:4176/api/requests      создать заявку
PATCH   http://127.0.0.1:4176/api/requests/101  поменять статус записи 101

POST принимает JSON с title. Тело в режиме нормальной работы может выглядеть как {"title":"Заявка на ремонт"}.
Для PATCH используй {"status":"closed"} или {"status":"open"}.
Исследуй фактический контракт через DevTools → Network. Сверяй статус операции, ответ и результат повторного GET.
Заявки стенда синтетические. Сервер хранит их до закрытия. В интерфейсе есть сброс списка.

Встроенные тренажёры
В JavaScript-заданиях собирай решение из предложенных частей и смотри результаты на фикстурах.
SQL-проверка выполняет поддерживаемое подмножество SELECT/JOIN над учебным набором строк.
Свободные ответы проверяй по критериям и разбирай на ревью. Приложение хранит текст и ссылки на результаты.
